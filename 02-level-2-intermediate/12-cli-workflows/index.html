    CLI Workflows¶

    Terminal-Based AI Development Patterns¶

    🎯 Overview¶

    Command-line workflows combine shell scripts, git operations, build tools, and AI assistance to create efficient development pipelines. Learn how to leverage Claude through the terminal for everything from code generation to deployment automation.

    Time to Master: 3-4 hours
    Outcome: Master CLI-based AI-assisted development workflows

    💡 CLI vs. Web Interface¶

    Why CLI Matters¶

    Advantages: 

    ✓ Direct file system access
✓ Execute commands immediately
✓ Integrate with existing tools (git, npm, etc.)
✓ Scriptable and automatable
✓ Persistent context
✓ Faster iteration cycles
✓ Better for large codebases

    When to use CLI: - Multi-file changes - Git workflows - Build/test automation - Deployment tasks - Repository analysis - Refactoring projects

    When to use Web: - Quick questions - Learning/exploration - Code snippets - No local project - Sharing conversations

    Workflow: Database Schema Evolution¶

    $ claude "Create migration to add user roles"

Claude: I'll create a migration for user roles:

Schema changes:
1. Create roles table
2. Create user_roles junction table
3. Add default 'user' role
4. Seed admin/moderator roles

[Creates migrations/005_add_user_roles.sql]

-- Create roles table
CREATE TABLE roles (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL,
  description TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Create junction table  
CREATE TABLE user_roles (
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  role_id INTEGER REFERENCES roles(id) ON DELETE CASCADE,
  granted_at TIMESTAMP DEFAULT NOW(),
  PRIMARY KEY (user_id, role_id)
);

-- Seed default roles
INSERT INTO roles (name, description) VALUES
  ('user', 'Standard user'),
  ('moderator', 'Can moderate content'),
  ('admin', 'Full system access');

-- Give existing users the 'user' role
INSERT INTO user_roles (user_id, role_id)
SELECT u.id, r.id 
FROM users u
CROSS JOIN roles r
WHERE r.name = 'user';

Review migration? (y/n)

$ y

Claude: Migration looks good. Run on development DB?

$ y

    🎯 Pipeline Automation¶

    CI/CD Integration¶

    .github/workflows/ai-review.yml: 

    name: AI Code Review

on: [pull_request]

jobs:
  ai-review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: AI Code Review
        run: |
          claude "Review this PR for:
          - Security vulnerabilities
          - Performance issues
          - Best practice violations
          - Test coverage gaps

          PR diff: $(git diff origin/main...HEAD)"

      - name: Comment on PR
        if: failure()
        uses: actions/github-script@v6
        with:
          script: |
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              body: process.env.CLAUDE_OUTPUT
            })

    ✅ Best Practices¶

    Effective CLI Usage¶

    DO: ✅ Use Claude for complex multi-step tasks
    ✅ Let Claude execute commands directly
    ✅ Review generated code before committing
    ✅ Use Claude for code reviews
    ✅ Integrate with existing tools
    ✅ Maintain conversation context
    ✅ Ask for explanations when needed

    DON'T: ❌ Paste large file contents (let Claude read)
    ❌ Run destructive commands without review
    ❌ Skip testing after AI changes
    ❌ Ignore AI suggestions without understanding
    ❌ Use for simple one-liner tasks

    Security Considerations¶

    Always review: - Database migrations - Security-related code - Credential management - API endpoint changes - Permission/authorization logic

    Never blindly execute: - Destructive commands (rm -rf, DROP TABLE) - Production deployments - Security configuration changes - Dependency removals

    🚀 Pro Tips¶

    Tip 1: Context Files¶

    Create .claude/context.md: 

    # Project Conventions

## Git
- Branch naming: feature/*, bugfix/*, hotfix/*
- Commit format: Conventional Commits
- Always squash feature branches

## Testing
- Minimum 80% coverage
- Tests required for all new features
- E2E tests for critical paths

## Deployment
- Staging before production
- Run smoke tests after deploy
- Rollback if any test fails
